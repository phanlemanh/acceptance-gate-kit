Billing Platform in context

One system at the centre, drawn as a sealed box: who leans on it, what it leans on, and the purpose written on every line between them. Nothing about how it is built inside — that question belongs to the next diagram down.

THE HEADLINE

One box, named by its duty

The coral box is the only thing in scope. Its sublabel — issues invoices, collects payment, exports ledger — is a promise, not a stack. No language, no framework, no database appears anywhere on it, so the diagram survives a rewrite.

Every line states a purpose

  • Six arrows, six labels — no bare connectors
  • Purpose in caps, protocol in the line beneath
  • People push in from above in muted grey
  • Outbound API calls leave in blue

What is missing on purpose

No services, queues, or databases sit inside the focal box, and no arrow crosses into it. The moment you need those, this stops being the right drawing — go one level down to the architecture diagram.
