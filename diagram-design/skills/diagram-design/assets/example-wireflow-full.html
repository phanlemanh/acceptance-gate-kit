Password reset flow

Five screens from locked-out to signed-in. Screens are skeleton frames — gray bars, one input, one button — and every edge names the tap that causes it. The dashed edge is the expired-link detour back to the request screen.

WHY A WIREFLOW

The screen is the unit

When the reader's question is "what do I see, and where does this tap take me?", the surface matters. Logic lives on the edges; screens live in the nodes. If branching dominated instead, this would be a flowchart.

Skeletons, not mockups

  • Gray bars, never readable copy
  • One input, one button per screen
  • Titlebar names every screen
  • Accent only on the key CTA

Every edge is an action

Each connector is labeled with the tap that fires it. The one branch — expired link — is dashed and labeled, so the unhappy path reads at a glance.
